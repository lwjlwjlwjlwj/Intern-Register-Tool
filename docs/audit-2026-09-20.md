##### 🔴 修正初稿的一处措辞：只读段**不是**"共同段"

初稿把「只读 / 建 key / 校验」称作"共同的三个 HTTP 段"。逐行核对后：
**只有"调用序列"相同，字段面与错误面都不同** —— 最硬的一条是 #10：
`stage_login_key` **一次都不调 `list_keys`**，而 `run_one` 调。把只读段做成一个
函数并让 A 也走它，等于给流水线**加一次 HTTP 请求**；而 A 的只读+建 key 是**包在同一个
`try` 里**的，`list_keys` 抛异常会让一个原本成功的账号变成 `status=failed`。
⇒ **那不是零值变化**，是静默的行为变更。

##### 真实重叠量：约 18 行

把两边"非注释、非 log、非持久化"的行挑出来数：

- 只读段：A 5 行（`get_user_info`/`free_grant_status`/`claim_free_grant`/`balance` +

持久化字段、错误分支）合计 60 行以上。

## 10. 本轮踩坑（写下来才算收回成本）

1. **🔴 导入图扫描器漏掉了 `from src import a, b` 的子模块边。**
   第一版把 `from src import pipeline, quota` 记成一条 `-> src` 的边（因为
   `ast.ImportFrom.module == "src"`，而 `names` 才是真正的子模块）。
   后果：**扇入/扇出全错，环检测会漏报** —— 如果环恰好由 `from src import x` 构成，
   会得出"0 个环"的假结论。
   本项目这次是**真 0 环**，但那是运气，不是方法对。
   **判据**：`ImportFrom` 的**每个 alias 都要单独算一条边**，不能只取 `module`。

2. **"未引用定义"扫描会把 pytest 用例和 autouse 夹具全报成死代码。**
   237 条候选里 **231 条是假阳性**（`tests/` 用例 + `_isolate_runtime_state`）。
   与 `deep-codebase-audit-landing` 的 *"Tools cannot tell code from prose about code"*
   同族：工具也分不清"被框架**按名字**调用"和"没人用"。
   **判据**：判据必须排除 `tests/`，且夹具/回调类名字不能靠文本引用判定。
   最终只报 **6 条**，其中 5 条经全仓 grep 二次确认。

3. **🔴 "引用它的文件数"和"出现次数"是两个分母。**
   扫描器先输出 `src/browser_login.py (referenced by 16 files)`，被 `grep -rln`
   打脸 —— 实际是 **2 个文件 / 16 次**。
   与 skill §3 的 *"count hits, don't count matching lines"* 完全同型：
   同一个 grep 会把一次事件的多个回声算成多次事件。
   **规矩**：报告里凡出现"N 个文件"，必须标明这是**去重后的文件数**还是**匹配次数**。

4. **`.workbuddy-ai/` 必须排除在"死文件"判定之外。**
   其中 `tmp/` 里的脚本被 `docs/refactor-plan-2026-09-19.md` 等**点名当证据引用**，
   当"零引用草稿"清理会让公开仓库里的引用悬空。这与 `memory/MEMORY.md` §9 的既有
   结论一致 —— 本轮再次确认，没有新情况。

5. **`git status -sb` 的 `[gone]` 陷阱本轮未复现**：显示 `## main...origin/main`，
   远端 ref 正常。说明上次的收尾修复（重建 `.git/refs/remotes/origin/main`）是持久的。

6. **🔴 "路径不存在"不等于"引用坏了" —— 路径校验必须读上下文。**
   本轮我先报了 2 条 🔴 文档悬空引用（README 里的时间戳快照 + `selftests/*`），
   **读完上下文后两条全部撤销**：
   - 一条在**代码块里的目录布局示意**中（旁边就并排着真实存在的那份快照）；
   - 一条原句写着"**已于 2026-09-19 移除**"，本身就是历史记录。

   与 skill 的 *"Tools cannot tell code from prose about code"* 同型，但这次是
   **"工具分不清『引用一个真文件』和『提到一个文件名』"**。
   我的扫描器输出的是 `(路径, 文件数, 次数)` 三元组 —— **缺了"上下文类型"这一维**。
   **判据**：路径存在性检查必须至少再判两件事：① 该行是否落在代码块里（示意清单）；
   ② 该行邻近是否有"已移除/已删除/原/历史"这类标记词。
   **假阳性比漏检更坏** —— 它会逼人改一份本来正确的 README，并消耗下一次审计的信任。

7. **🔴 `Path.write_text()` 在 Windows 上会把 `\n` **再**翻译一次，`\r\n` 变成 `\r\r\n`。**
   B5 搬运时我先按 `\r\n` 拼好整份 `run.py` 再 `write_text`，结果每行多出一个裸 `CR`。
   **文件照样能跑、测试照样全绿** —— 因为 Python 读源码时容忍裸 CR，
   只有 `git diff` 会显示整个文件被改写（那一瞬间很容易被当成"格式规范化"提交上去）。
   同一条路上还有第二个坑：`read_text()` 默认做 universal-newline 翻译，
   于是 `assert text.count("\n") == text.count("\r\n")` 这种"是不是纯 CRLF"的断言
   **永远为真**（等于没断言）—— 必须走 `read_bytes().decode()`。
   **判据**：读写带换行的文本，用 `read_bytes()` / `write_bytes()`，不用文本模式；
   改完打印 `CR / LF / CRLF / bare-CR` 四个计数自证。

8. **🔴 金标准夹具不能带机器绝对路径 —— 泄漏闸门会拦。**
   `render_batch_report` 印的是 `written.resolve()`，于是夹具里自然带上了
   本机仓库根的绝对路径（`<盘符>:\epsoft\...\results-*.json`）。
   而 `check_leaks.py` 的 `ABS_PATH_RE` 恰好匹配
   `[A-Za-z]:[\\/](Users|IDE|epsoft|tools|dev|code)`，且第 2 层高熵扫描覆盖 `.json`
   （`tests/fixtures/` 就在扫描面里）。
   ⚠ **本条就是在写这一段时踩到的**：上一稿把这行路径原样写进本文档，
   立刻被闸门拦下（`docs/audit-2026-09-20.md:514`）—— 说明闸门有效，
   也说明"在文档里讲绝对路径"本身就会命中。
   **修法**：夹具里存 `<WRITTEN>` 占位符，比对前做替换。
   ⚠ 但**中性化会把它要防的回归一起吞掉**（"路径没 resolve"也变成 `<WRITTEN>`），
   所以必须**再单独断言一次被中性化的那部分** —— `assert str(WRITTEN.resolve()) in got`。
   这条与 skill 的 *"脱敏会自命中"* 同族：**任何"抹掉一段输出"的处理都要配一条
   "那段输出本来应该长什么样"的独立断言。**

9. **静态接线检查在"搬家"时必须跟着改靶，且"找不到"要算失败。**
   `test_labels_and_values_share_one_print_call` 原本扫 `run.py`；print 搬进
   `src/report.py` 后若忘了改靶，`len(hits)` 会变成 0 ——
   写成 `assert len(hits) == 1` 会大声失败（好），
   但写成 `<= 1` 或"找不到就跳过"就会变成**永远为真**的假绿（坏）。
   另外**只改靶不够**：还要加一条"旧位置不该再有"的反向护栏，
   否则"只搬一半"（两处并存）时两条测试各看一半、都是绿的。

10. **🔴 `.gitignore` 的例外是"逐文件手写"的 ⇒ 每加一个夹具都要重踩一次。**
    B5 把金标准写进 `tests/fixtures/report_render_golden.json` 后，
    `git status` **根本不显示它**（被 `.gitignore` 的 `*.json` 吞了）。
    失败形态是最坏的一种：**本地 pytest 全绿**（文件就在磁盘上），
    新克隆的仓库 / CI 直接 `FileNotFoundError`。
    这与 `.gitignore` 里 `!tests/fixtures/ledger_sample.json` 上面那段注释记录的
    **CI 第二次变红**是同一个坑 —— 教训写下来了，但**没有变成断言**，所以照踩。
    **修法两层**：① 补 `!tests/fixtures/report_render_golden.json`（仍然逐文件，
    不能写成 `!tests/fixtures/*` —— 那会把真凭据一起放行）；
    ② 补 `tests/test_repo_hygiene.py`：`tests/fixtures/` 下**每个**文件
    `git check-ignore` 都必须返回"未被忽略"，并给扫描面本身加守卫
    （目录改名会让参数化测试**静默消失**而不是失败）。变异验证：摘掉那行例外 ⇒ 立刻红。
    ⇒ 与 §6 同一条通用规律：**"人记得做 X"不是护栏；把 X 变成断言才是。**
